# Design reference vault

Open this directory as an Obsidian vault, or import its Markdown notes and assets into the assistant when that feature is implemented. This is an initial folder structure, not an implemented app importer.

- `references/` — curated references, grouped by feature tags rather than just visual style.
- `assets/` — screenshots and assets you have permission to use. Link them from the relevant note.
- `templates/reference.md` — duplicate this for each new reference.
- `decisions/` — record which references influenced a build and why.

Each note should explain a useful mechanism. “Looks clean” is too vague. Describe what the hierarchy, interaction, composition or content sequence accomplishes and where it would help.

Keep original URLs and dates. Record whether an observation came from an actual rendered page, a screenshot or source code. A personal interpretation is not the original designer's stated principle.

To grow the library, add one well-annotated reference at a time, then test whether a brief retrieves the right examples. Bulk importing unlabelled screenshots alone will not establish reliable retrieval.
